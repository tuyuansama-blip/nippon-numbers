# footy-ev 技術スパイク設計書

**結論**: Dixon-Coles（時間減衰・リッジ収縮つき）を scipy L-BFGS-B で最尤推定し、2012/13〜2024/25 を試験期間とするウォークフォワードで RPS/log-loss を Pinnacle クローズドオッズ（Shin法でマージン除去）と対比する。合格基準は「市場に勝つこと」ではなく `gap_closed ≥ 0.60`（RPS で市場との差 ≤ +0.017）。市場に有意に勝った場合は成功ではなくリーク疑いとして FAIL 扱いにする。

## 1. モデル: 時間減衰つき Dixon-Coles

### 1.1 パラメータ化

```
θ = ( μ0, γ, {a_i}, {d_i}, ρ )        # i = 学習窓に現れる全チーム
log λ_k = μ0 + γ + a_h(k) - d_a(k)    # ホーム得点期待値
log μ_k = μ0     + a_a(k) - d_h(k)    # アウェイ得点期待値
X_k ~ Poisson(λ_k), Y_k ~ Poisson(μ_k), 低スコア域のみ τ で補正
```

- `μ0` はリーグ平均得点水準の切片、`γ` はホームアドバンテージ（グローバル1本）。
- `d_i` は「守備の強さ」（大きいほど失点しにくい）。符号を `-d` で入れる。
- **識別性はハード制約（Σa=0）ではなくリッジで担保する。** `μ0` を明示的に置いたうえで a,d に事前分布を掛ければ縮退は解け、制約付き最適化を避けられる。実装が単純になり、昇格チームの扱いと同じ機構で処理できる。

Dixon-Coles 補正項:

```python
def tau(x, y, lam, mu, rho):
    t = np.ones_like(lam)
    t = np.where((x==0)&(y==0), 1 - lam*mu*rho, t)
    t = np.where((x==0)&(y==1), 1 + lam*rho,    t)
    t = np.where((x==1)&(y==0), 1 + mu*rho,     t)
    t = np.where((x==1)&(y==1), 1 - rho,        t)
    return np.maximum(t, 1e-10)      # τ<=0 で log が落ちるのを防ぐ床
```

`ρ` は `[-0.20, 0.20]` に bounds を掛ける（DC 原論文の推定値は約 -0.13）。床でクリップした試合数を fit のメタに記録し、常時 0 でないなら bounds が狭すぎる合図。

### 1.2 目的関数（罰則つき重み付き対数尤度）

```
ℓ(θ; T) = Σ_k w_k [ log τ_k + x_k log λ_k - λ_k + y_k log μ_k - μ_k ]
          - (1/2σ²) Σ_i [ (a_i - m_a(i))² + (d_i - m_d(i))² ]

w_k = exp(-ξ · (T - t_k))          # T = 予測対象日, t_k = 試合日, 単位は日
```

最小化するのは `-ℓ`。`scipy.optimize.minimize(method="L-BFGS-B", jac=grad)`。

**解析勾配を必ず実装すること（最重要の性能判断）。** パラメータ数 ≈ 2×35+3 ≈ 73 で、数値勾配だと 1 fit あたり 74 倍の関数評価になり、チューニング総 fit 数（1万回超）が現実的でなくなる。Poisson 部は閉形式:

```
∂ℓ/∂a_h += w(x-λ)   ∂ℓ/∂d_a -= w(x-λ)
∂ℓ/∂a_a += w(y-μ)   ∂ℓ/∂d_h -= w(y-μ)
∂ℓ/∂γ    = Σ w(x-λ)
∂ℓ/∂μ0   = Σ w[(x-λ)+(y-μ)]
```

τ 部は 4 セルのみで、`∂log τ/∂λ` 等も閉形式。リッジ部は自明。チーム別の集約は `np.add.at` で。

**さらに warm start を必ず入れる。** ウォークフォワードで1節進んでも θ はほぼ動かない。前回の解を初期値にすると L-BFGS の反復が 5〜10 分の1になる。

### 1.3 時間減衰係数 ξ の選び方

- 半減期で表現する: `ξ = ln2 / HL`。グリッドは `HL ∈ {60, 90, 120, 180, 250, 365, 550, 800, ∞}` 日。
- **選択基準は in-sample 尤度ではなく、チューニング期間上で本番と同一プロトコルのウォークフォワードを回したときの平均 RPS。** in-sample 尤度は必ず ξ→0（減衰なし）を選んでしまう。
- 探索は coarse-to-fine の2段: ① σ=0.35 固定で HL を9点掃く → ② 最良 HL 固定で `σ ∈ {0.15, 0.25, 0.35, 0.5, 0.8}` を掃く。総 fit 数 ≈ 3,400、warm start ありで 1〜2 時間。一度だけ回して凍結する。
- 参考値: DC 原論文の ξ=0.0065（半週単位）は日換算 0.00186、半減期約 373 日 ≒ 1シーズン。グリッドはこれを中心に張ってある。
- 学習窓は「直近6シーズン」で打ち切る。半減期の4倍より古い試合の重みは 6% 未満で、計算量だけが増える。

### 1.4 昇格チームの初期値

**加法的な固定効果ではなく、事前分布の中心をずらす形で入れる。**

```
m_a(i) = π_a,  m_d(i) = π_d   ... i が「PL 1年目」のとき
m_a(i) = 0,    m_d(i) = 0     ... それ以外
```

- 開幕前（試合数0）のチームは尤度からの引きが無いので θ_i = (π_a, π_d) ちょうど、すなわち「過去の昇格組の平均像」になる。試合が溜まるにつれ尤度が事前分布を押し切る。加法オフセットにすると、a_i が学習したあとも下駄が残って二重計上になる。この形なら起きない。
- `(π_a, π_d)` はチューニング期間で「PL 1年目のチームのシーズン終了時点の推定 a,d」の平均として一度だけ求め、**凍結して試験期間には触らせない**。
- 事前登録アブレーション: `π=(0,0)`（＝リーグ平均に収縮）との比較を、**昇格チームが絡む試合のみ**に絞った RPS で報告する。ここに差が出ないなら π は捨ててよい。

> より正しいがコスト高の案として「E1（Championship）の試合をリーグレベルオフセット付きで尤度に入れる」がある。E1 CSV は同一サイト・同一スキーマなのでデータ層だけの変更で済む。スパイクではやらないが、ローダは初日から `Div` を保持し複数ディビジョンを受けられる形にしておくこと（§4）。

### 1.5 スコア行列 → 1X2

```python
K = 12                                   # P(X>12 | λ≈1.6) < 1e-8
M = np.outer(pois_pmf(K, lam), pois_pmf(K, mu))
M[:2,:2] *= tau_matrix(lam, mu, rho)     # 低スコア4セルのみ
M /= M.sum()                             # τ 補正と打切りの両方をここで吸収
p_home = np.tril(M, -1).sum(); p_draw = np.trace(M); p_away = np.triu(M, 1).sum()
```

## 2. 検証プロトコル

### 2.1 期間の事前分割（一度決めたら動かさない）

| 期間 | シーズン | 用途 |
|---|---|---|
| WARMUP | 1995/96 – 1999/00 | 学習データとしてのみ使用 |
| **TUNE** | 2000/01 – 2011/12 | ξ, σ, π, ρ の初期値、すべての設計判断。PSC オッズが存在しない期間と一致しており、市場と比較しようがない = 構造的にリークしない |
| **TEST** | **2012/13 – 2024/25**（13季, n≈4,940） | 一度だけ回す。PSCH/PSCD/PSCA 全期間で利用可 |

TUNE と TEST の境界を「クローズドオッズの初出年」に合わせたのが要点。ハイパーパラメータが市場ベンチマークを覗く経路が物理的に存在しない。

### 2.2 ウォークフォワード

- **拡張窓（直近6シーズンで打切り）+ 時間減衰。** 固定窓長は使わない。減衰が事実上の窓長を決める。
- **再推定頻度: 試合が存在する日ごと**（`--refit date`）。予測対象日 `D` の直前に `date < D` の全試合で fit。PL は週あたり2〜3日に分散するので年 ≈ 110 fit、13季 ≈ 1,430 fit。warm start ありで 10〜25 分。`--refit week`（月曜まとめ、年 ≈ 40）を高速オプションとして用意。
- 予測は現 PL 20 チームのみ。降格済みチームの試合も**尤度には残す**（強さのスケールを繋ぐアンカーになる）。
- フォールド境界が同一日を割らないことを保証する。

### 2.3 リークの防止（keiba の asof.py 教義の移植）

1. **`date < kickoff_date` の厳格フィルタ。** `Time` 列は 2019/20 以降にしか無いので、同日試合は一律「使わない」に倒す。行順ベースの `shift` は禁止。
2. ハイパーパラメータ（ξ, σ, π, ρ bounds, K, 打切り窓長）は TUNE 期間で確定し、run メタデータにハッシュ付きで記録。試験実行はそれを読むだけ。
3. **オッズはモデル入力に一切入れない。** ベンチマーク専用。同時に、スパイクは EV も賭けも出さない（§5）。
4. **未来削除不変テスト**（keiba `test_features_leak.py` の直輸入）: 日付 `D` 以降の全試合を削って再 fit し、`D` の予測が**ビット単位で一致**することを assert。
5. 欠損 PSC の試合は head-to-head 比較から除外し、除外件数をレポート冒頭に出す。モデル単独指標には残す。

### 2.4 マージン除去

**主: Shin 法**（π_i = 1/o_i、Σπ = s として `brentq` で z ∈ (0, 0.4) を解く）。

```
p_i(z) = ( sqrt(z² + 4(1-z)·π_i²/s) - z ) / ( 2(1-z) ),  Σ p_i = 1 を満たす z を求める
```

**併記必須: 単純正規化（multiplicative）。** 実測で両者の差は RPS 0.0001（Pinnacle のマージンが 2.9% と薄いため）。レポートに両方を出し「除去方式は結論を動かさない」ことを毎回示すこと。冪法・オッズ比法は不要（§6）。

対象列は `PSCH/PSCD/PSCA` 固定。`Max*/Avg*` は使わない（ブック横断の最良値は取引不能な合成価格）。

### 2.5 評価指標

```python
def rps(p, y):                    # p は H,D,A の順
    e = np.zeros(3); e[y] = 1
    cp, ce = np.cumsum(p), np.cumsum(e)
    return 0.5*((cp[0]-ce[0])**2 + (cp[1]-ce[1])**2)
```

- RPS（主）と多クラス log-loss（従）。
- **判定は必ずペア差 `d_k = RPS_model,k - RPS_market,k` の平均に対して行う。** 水準はシーズン難易度で 0.180〜0.209 も動く。
- CI は **節（matchweek）単位のブロックブートストラップ**、n_boot=2000、seed=42。同一節の試合は同一の推定 θ を共有し誤差が相関するため、試合単位のリサンプルは CI を過小評価する（keiba が「bet ではなく race をリサンプルする」としたのと同じ理由）。
- 比較対象は3本立て:

| 名称 | 中身 |
|---|---|
| `climatology` | 減衰つきローリングで推定した H/D/A 基準率（ウォークフォワードで honest に更新） |
| `market` | Pinnacle クローズ, Shin |
| `dc` | 本モデル |

- **`gap_closed = (RPS_clim - RPS_model) / (RPS_clim - RPS_market)`** — keiba の `blind_gap_closed` の直移植。0 = 何も知らないのと同じ、1 = 市場と同等。これが判定の主指標。
- 較正: ①予測確率バケット別の予測 vs 実測（アウトカム別）、②市場含意確率のデシル別、③引き分け専用チェック（DC は引き分けを外しやすい）。
- 診断のみ（判定には使わない）: シーズン別 `gap_closed`、`seasons_within_threshold` 件数。

## 3. 合格基準（事前固定・実行前に凍結）

TEST 期間 n≈4,940 のプールされたペア差に対して判定する。実測ベースライン `RPS_clim - RPS_market = 0.0422`, `LL 差 = 0.125`。

| 判定 | 条件 |
|---|---|
| **STRONG** | `gap_closed_RPS ≥ 0.75`（RPS ≤ 0.2013、市場との差 ≤ +0.011） |
| **PASS（健全）** | `gap_closed_RPS ≥ 0.60`（RPS ≤ 0.2076、市場との差 ≤ +0.017）かつ ペア差の 95% CI 上限 ≤ +0.022 かつ `gap_closed_LL ≥ 0.55` かつ 較正条件（下記）を満たす |
| **WARN** | `0.40 ≤ gap_closed_RPS < 0.60` — 動いてはいるが何かを取り逃がしている。アブレーションへ |
| **FAIL** | `gap_closed_RPS < 0.40`、または較正条件違反、またはリークテスト赤 |
| **FAIL-AUDIT（リーク疑い）** | `mean(RPS_market - RPS_model) > 0.005` かつ 95% CI 下限 > 0 — 成功ではない。監査対象。 |

較正条件（すべて必須）:
- 市場含意確率のデシルのうち n ≥ 150 の全ビンで `|model_mean - observed| ≤ 0.05`
- 全体で `|mean p_draw - 引き分け実測率| ≤ 0.02`
- レポートがブートストラップ SE を明示し、`SE ≤ 0.003`（設計上の分解能が閾値を解像できている証拠）

**根拠:**
- 0.60 の水準感 — 良質な DC 系モデルの公表水準は EPL で RPS 0.198〜0.207 に落ちる。実測の市場 0.1907・気候値 0.2329 に当てると `gap_closed` は 0.61〜0.79。0.60 はその下端に置いた「これを割ったら実装かデータが壊れている」線であり、「市場に勝つ」線ではない。
- FAIL-AUDIT の根拠 — Pinnacle のクローズドラインは 1X2 マージン 2.9%（実測）で、一般に入手できる最もシャープな価格。得点結果のみを使い、負傷・出場メンバー・移籍・日程過密を一切見ないモデルがこれに有意に勝つ確率は、バグ（学習窓に未来が混入、`FTHG` の特徴量化、日付パースずれ、試合後オッズの使用）より低い。「勝った」を無条件に喜ばない仕組みを判定表に埋め込むのが、keiba の「CI 下限で判定する」思想の本件版。
- 分解能 — 実測で n=2,280・週ブロックの CI 半幅は ±0.0056（sd 0.143 の大きな差に対して）。モデルと市場は高相関でペア差の sd はその 1/3〜1/5 になるため、n≈4,940 では ±0.002 前後。0.005 と 0.017 の両閾値を十分解像できる。

**明示的に基準に含めないもの: ROI・的中率・EV・資金曲線。** 理由は keiba DESIGN.md §3.1 の実測結論 — 市場にアンカーしていないブラインド確率をそのまま EV に入れると穴側で桁が狂う。精度が市場に届いていない段階で ROI を測る意味は無い。

`backtest` は末尾に **STRONG / PASS / WARN / FAIL / FAIL-AUDIT** をそのまま印字する（keiba の `== 判定 ==` ブロックと同じ体裁）。`reports/backtest_{run_id}.md` + `calibration_{run_id}.png` + `rps_by_season_{run_id}.png` を書く。

**`footy check` の項目**（安価な退行検知）:
- シーズンあたり 380 行、各チーム 38 試合（ホーム19/アウェイ19）
- `FTR` と `FTHG/FTAG` の整合、負値・欠損
- `1/PSCH + 1/PSCD + 1/PSCA` が [1.00, 1.10] に入るか（実測平均 1.0293、p99 1.0397）。ここがズレたら列の取り違え・パース退行
- PSC 欠損件数（シーズン別）
- `(date, home, away)` の重複
- チーム名の未知エイリアス → 0 件でなければ exit 1

**依存最小セット:** `requests, pandas, numpy, scipy, pyarrow, matplotlib, pytest`。scikit-learn も lightgbm も不要。`bin/footy` は venv 解決と `cd ROOT` のためだけのラッパ。

**テストの要点:**
- `test_leak.py`: 未来削除不変（§2.3-4）、フォールド境界が日を割らない、train 最終日 < test 初日
- `test_devig.py`: Shin の出力が Σ=1、単調、マージン0のオッズで恒等、`z` が [0,0.4) に収まる
- `test_metrics.py`: RPS の既知値（完全予測=0、`p=(1,0,0)` で A 的中=1.0）、ブロックブートストラップの決定性
- `test_dc.py`: 合成データで真値を回収できるか（既知の a,d,γ,ρ から試合を生成し、推定値が誤差内で戻ることを assert）。keiba の `tests/synth.py` 方式
- ネットワークアクセスは全テストで発生させない

## 6. 注意点

1. **`Date` 列のパースが実測の地雷。** 古いシーズンは2桁年、新しいシーズンは4桁年で混在する。`pd.to_datetime(d["Date"], dayfirst=True, format="mixed")` で通ることは確認済み。ここを黙って間違えると日付順が壊れ、リークが静かに入る。`check` で日付レンジがシーズンと整合するかを必ず検査すること。
2. **COVID 期間（2020-06-17 〜 2021-05-中旬、無観客）でホームアドバンテージが崩壊する。** `crowd=empty` フラグを事前登録し、主結果は「含む/除く」の両方を報告する。ただし判定は含むほうで行う（除いた結果で判定すると事後選択になる）。
3. **`tune` の計算量が唯一の実行時リスク。** 解析勾配と warm start の両方を入れないと、グリッド探索が数時間から十数時間に膨らむ。先に「1 fit の所要時間」を計測し、`(grid点数 × TUNE の fit 数)` を見積もってから本探索に入ること。1 fit が 0.5 秒を超えるなら、先に最適化を直す。
4. 未検証の前提: DC 到達水準（RPS 0.198〜0.207）は公表研究からの引き当てであり、本データ・本実装での実測ではない。初回実行で `gap_closed` が 0.40 を大きく下回った場合、閾値が厳しすぎるのではなく実装が壊れている可能性を先に疑うこと（合成データでの真値回収テストが最初の切り分け）。

**不採用:** SQLite（入力が小 CSV 30 本で過剰）／Bb\*・Max\*・Avg\* 系オッズ（取引不能な合成価格）／冪法・オッズ比法のマージン除去（Shin と単純正規化の差が実測 0.0001）／ハード制約 Σa=0（リッジで識別できる）／固定長ローリング窓（時間減衰と役割が重複）／昇格チームへの加法固定効果（二重計上になる）／in-sample 尤度による ξ 選択（必ず減衰なしを選ぶ）／試合単位のブートストラップ（CI を過小評価）／RPS 水準そのものでの合否判定（シーズン難易度で動く）。
